# Claude Code Target Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A third generated output, `agents-claude/`, installed into the Claude Code config dir, so the Claude Code model can spawn the same clean-room skill agents (and the `skill-router`) from any project on a Claude subscription.

**Architecture:** Reuse `discoverSkills` and the manifest. Add a Claude renderer (markdown + frontmatter, same skill-table idea as the Vibe TOML), a writer into the committed `agents-claude/`, and an installer that copies validated, marker-owned files into `<claudeHome>/agents/`, adds Read allow rules, and syncs a Claude `route-skill`. `runFlow` and status gain a Claude step/column. Nothing touches credentials or calls Anthropic.

**Tech Stack:** Node ESM (`scripts/generate.mjs`), plain-assert test registry in `scripts/test.mjs` (`node scripts/test.mjs`), bash `install.sh`.

**Spec:** `docs/superpowers/specs/2026-11-09-claude-code-target-design.md` (read it with this plan; its "My calls" and "Revisions after SME review" sections are binding).

## Global Constraints

- Manifest stays the single source of truth; every Claude artifact is derived, idempotent, regenerable. pi and Vibe output bytes stay identical.
- Agent frontmatter is exactly: `name`, `description`, `tools: Read, Grep, Glob`, `omitClaudeMd: true`. No `Skill`, no MCP tools, no `Agent`. A file missing its `tools:` line would inherit every tool, so the installer refuses any source that lacks it (Task 2).
- Ownership: a generated Claude agent file ends with the line `<!-- generated by skill-router -->`. `isOwnedClaudeAgent` (Task 1) is the only ownership test, used by prune and installer alike.
- The installer never writes, overwrites or deletes anything that is not an owned regular file; symlinked or unowned destinations are refused and reported (a warning, never a failure).
- Paths in generated files use `tildePath()` like the Vibe target. The allow rules are built from realpaths.
- Claude config dir: `$CLAUDE_CONFIG_DIR` (must be absolute and an existing directory, else warn and skip) or `~/.claude`. The Claude install runs only if the dir exists. `--no-claude` on the CLI skips it. Generation of `agents-claude/` always runs.
- `runInstall`/`runUpdate`/`statusOf`/`printStatus` take the Claude dir as an explicit parameter; `null` and `undefined` both mean "skip the Claude install step". Only the CLI computes the default. Do not copy the existing `??`-default pattern for it.
- Settings edits: atomic write, `.bak` (mode 0600) before change, original file mode preserved, symlinked `settings.json` resolved first, unparseable or unexpected shapes never touched, idempotent, exact manual remedy printed when skipped.
- Never read, write or reference credentials, tokens or API keys.
- Minimum Claude Code version for `omitClaudeMd` is 2.1.271; older clients ignore unknown fields silently (README must say so).

## Review Focus

- A hand-written or symlinked `~/.claude/agents/<name>.md`, or one that merely quotes the marker mid-file, is untouched and reported (Task 2).
- A truncated or hand-edited `agents-claude/` source lacking `tools: Read, Grep, Glob` is never installed (Task 2).
- `~/.claude` absent, `--no-claude`, or `claudeHome` null/undefined: nothing written under the real home, exit unaffected (Task 4).
- `settings.json` unparseable, top-level non-object, `permissions` non-object, `allow` non-array, or symlinked: untouched or merged safely (Task 3).
- Description/persona containing quotes, colon, `\r`, NEL, U+2028 stays valid one-line YAML and cannot inject a frontmatter line (Task 1).
- Checkout outside the home dir or with glob characters in its path (Tasks 1, 3).
- A repo removed from the manifest disappears from `~/.claude/agents/` in one run; an empty or absent source never mass-deletes (Tasks 2, 4).

### Task 3: Read allow rules and Claude `route-skill`

**Files:**
- Modify: `scripts/generate.mjs`
- Create: `global-skills-claude/route-skill/SKILL.md`
- Test: `scripts/test.mjs`

**Interfaces:**
- Produces:
  - `export function claudeReadRules(repoRoot, home = os.homedir()): { rules: string[], error?: string }` — two rules for `skills/**` and `catalog/**`, from `realpathSync(repoRoot)` (so the router can read its catalog): `Read(~/<rel>/skills/**)` under the (real) home, else `Read(//<abs-without-leading-slash>/skills/**)`. `error` set, `rules` empty, when the path contains any of `*?[]{}()`.
  - `export function mergeClaudePermissions(settingsPath, rules: string[]): { changed: boolean, added: string[], error?: string }` — adds only missing rules (an equivalent `~/` or `//` spelling counts as present); creates the file when absent; resolves a symlinked `settings.json` to its real path; writes `.bak` (0600) before changing, preserves the original file mode, re-stats size/mtime just before rename and aborts with an error if it changed; errors without writing on unparseable JSON, a top-level value that is not a plain object, `permissions` present but not an object, or `allow` present but not an array.
  - `export function hasClaudeReadRules(settingsPath, rules: string[]): boolean` — read-only; false for a missing or unparseable file.
  - `export const GLOBAL_SKILL_MARKER = "overwritten by skill-router install/update"` (substring of the boilerplate comment in the Claude `route-skill`).

The existing `syncGlobalSkills` and pi paths are not changed.
  - `export function claudeSkillsState(root, skillsHome): "in-sync" | "stale"` — read-only byte compare.
