# route-skill Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A cross-repo skill router: a generated catalog of every skill in every pinned repo, a `skill-router` subagent that reads it and returns skill + path + digest, and a thin global `route-skill` that spawns that subagent.

**Architecture:** `generate.mjs` already discovers every SKILL.md in every clone (`discoverSkills`). Add two derived outputs to the same flow: `catalog/skill-catalog.md` (one table row per skill, `~`-anchored path) and `agents/skill-router.md` (a single non-per-repo agent whose persona is routing over that catalog). The global skill is a committed file the installer syncs into `~/.pi/agent/skills/route-skill/`. The calling session never loads the catalog; only the subagent reads it.

**Tech Stack:** Node ESM (`scripts/generate.mjs`), `node:test`-style plain assert tests in `scripts/test.mjs` (existing pattern: local `test()` registry, tmp dirs, `node scripts/test.mjs`), bash `install.sh`.

**Spec:** `docs/superpowers/specs/2026-11-05-route-skill-design.md`

## Global Constraints

- Manifest stays the single source of truth; catalog and router agent are derived, regenerable, idempotent.
- Catalog paths are `~`-anchored via existing `tildePath()` (machine-independent in git).
- The router agent must NOT carry `skills:`/`skillPath` frontmatter (it owns no skills) and must set `inheritSkills: false`.
- `prune()` must never delete `agents/skill-router.md` — it only deletes generated per-repo agents (marker: `skillPath: ../skills/<name>` and name not in manifest), and the router agent has no such marker; add a test pinning this.
- Router agent persona includes: recommend-and-stop (never execute), open the winning SKILL.md and return a digest, name the `~`-anchored path, note near-miss alternatives when two skills are close.
- Global skill body is thin: capture the user's situation, spawn the `skill-router` subagent with it, relay the result verbatim, then offer to read the recommended SKILL.md.
- No Vibe target for the router in this plan (spec non-goal).

## Review Focus

- Catalog goes stale relative to clones: pin that `writeSkillCatalog` output equals a fresh `discoverSkills` render in `statusOf`-style comparison (Task 1 test).
- `~` expansion for checkouts outside the home dir: `tildePath` already returns absolute there — reuse it, don't re-implement (Task 1).
- Router agent colliding with a user agent named `skill-router`: same warning path as per-repo collisions is out of scope, but the agent file must be regenerated idempotently so a user edit is detected as "stale", never silently merged (Task 2).
- Empty repos (e.g. `graphify`, 0 skills): catalog section renders with no rows, not a crash; router agent still written (Task 1, Task 2).
- Global skill overwritten by user edits: installer overwrites unconditionally (it is generated-style boilerplate); document that in the skill header comment (Task 3).
- Catalog with duplicate skill names across repos: `discoverSkills` dedupes within a repo only; catalog rows must carry the repo name so cross-repo duplicates stay distinguishable (Task 1).

### Task 1: Generated catalog

**Files:**
- Modify: `scripts/generate.mjs` (new exports `renderSkillCatalog`, `writeSkillCatalog`; wire into `runFlow` and `statusOf`)
- Test: `scripts/test.mjs`

**Interfaces:**
- Consumes: `discoverSkills(cloneDir, entry)` → `{ skills: [{ name, dir, description }], ... }`; `tildePath(absPath, home?)`.
- Produces: `renderSkillCatalog(root, manifest, { home } = {})` → string (the full markdown file); `writeSkillCatalog(root, manifest)` → `{ written: <catalogPath>, skillCount: n }`. Catalog written to `path.join(root, "catalog", "skill-catalog.md")`.

Catalog format (machine-stable, git-diffable):

```markdown
# Skill catalog

Generated by scripts/generate.mjs from repos.json — do not edit.

## <repo-name>

- <skill-name>: <description> — <~/anchored/path/to/SKILL.md>
- <skill-name> — <path>          (when description is null)
```

Repos with zero skills get a `## <repo-name>` heading followed by the line `(no skills yet)`. Rows sorted by skill name within a repo; repo sections in manifest order.

  - Duplicate skill name across two repos: both rows present, each under its own repo heading.
  - `writeSkillCatalog` creates `catalog/skill-catalog.md`, returns `{ skillCount }` summing all repos, and is idempotent (second call, same content, no diff).
- [ ] **Step 2: Run tests, verify they fail** — `node scripts/test.mjs`; expected: `renderSkillCatalog is not a function` / assertion failures.
- [ ] **Step 3: Implement** `renderSkillCatalog` and `writeSkillCatalog` in `generate.mjs` per the format above; call `writeSkillCatalog` in `runFlow` right after `writeVibeAgentFiles`, and add a catalog row to the report (`catalog: N skills written`).
- [ ] **Step 4: Run tests, verify pass** — `node scripts/test.mjs` (all 114 existing + new).

### Task 2: Router subagent

**Files:**
- Modify: `scripts/generate.mjs` (new exports `ROUTER_AGENT_NAME = "skill-router"`, `renderRouterAgent({ catalogPath })`, `writeRouterAgent(root)`; wire into `runFlow` and `statusOf`)
- Test: `scripts/test.mjs`

**Interfaces:**
- Consumes: `writeSkillCatalog` result path; `tildePath`.
- Produces: `writeRouterAgent(root)` → `{ file: <path>, written: boolean }`; agent file at `agents/skill-router.md`.

Agent file shape:

```markdown
---
name: skill-router
description: "Routes a described situation to the best skill across all pinned repos; returns skill, path, and digest"
inheritSkills: false
---
<persona body>
```

Persona body (hand-written constant in `generate.mjs`, referencing the `~`-anchored catalog path):

- You are the skill router over every repo pinned in this repo's manifest. Read `<catalog path>` first.
- Match the caller's situation to the catalog. When two skills are close, open both SKILL.mds and say which one and why.
- Open the winning SKILL.md and return: skill name, its `~`-anchored path, why it fits, and a short digest of the real file — never answer from the description alone.
- Recommend and stop. Do not execute the skill, edit files, or start the work.
- If nothing fits, say so plainly; do not force a nearest match.

- [ ] **Step 1: Write failing tests**:
  - `renderRouterAgent` with a fake home: frontmatter has exactly `name: skill-router`, a `description:` line, `inheritSkills: false`, and NO `skills:` or `skillPath:` lines; body contains the `~`-anchored catalog path and the strings "Recommend and stop" and "digest".
  - `writeRouterAgent` writes the file and is idempotent (byte-identical on second call).
  - `prune` safety: build a fake `agents/` dir with `skill-router.md` (rendered content) plus a stale per-repo agent `gone.md` containing `skillPath: ../skills/gone`; run `prune` with a manifest lacking `gone` — `gone.md` removed, `skill-router.md` still present.
  - Empty-clone repo in manifest: `writeRouterAgent` unaffected (it is not per-repo).
- [ ] **Step 2: Run tests, verify they fail.**
- [ ] **Step 3: Implement** `renderRouterAgent`/`writeRouterAgent`; call from `runFlow` after `writeSkillCatalog`; in `statusOf`, add a router row (`ROUTER` column value `in-sync`/`stale`/`missing` by comparing on-disk bytes to `renderRouterAgent` output) and include it in the `ok` computation.
- [ ] **Step 4: Run tests, verify pass.**
- [ ] **Step 5: Smoke** — `node scripts/generate.mjs install && node scripts/generate.mjs status`; status shows the router row `in-sync`; `git diff agents/skill-router.md` shows the new file.
- [ ] **Commit:** `feat: generate skill-router subagent over the catalog`

### Task 3: Global route-skill + installer sync

**Interfaces:**
- Consumes: `ROUTER_AGENT_NAME`.
- Produces: `syncGlobalSkills(root, skillsHome)` → `{ written: [<files>], skipped: n }`; copies every `global-skills/<name>/SKILL.md` to `<skillsHome>/<name>/SKILL.md` (default `<skillsHome>` = `~/.pi/agent/skills`), overwriting (boilerplate is machine-generated; header comment in the SKILL.md says so).

```markdown
---
name: route-skill
description: Route a described situation to the best skill across all skill-router repos, via the skill-router subagent
---
<!-- Generated-style boilerplate; overwritten by skill-router install/update. -->
Take the user's situation ... spawn the `skill-router` subagent (agent
name: `skill-router`) with the situation as its task ... relay the
recommendation verbatim ... then offer to read the recommended SKILL.md
and follow it in this session.
```
