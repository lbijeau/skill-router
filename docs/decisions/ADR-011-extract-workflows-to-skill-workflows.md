# ADR-011: Extract the workflows module to skill-workflows

Date: 2026-11-14

## Status

Accepted. Fires and executes ADR-009's split trigger.

## Context

ADR-009 kept workflows inside skill-router with a named split trigger:
extract when a workflow needs to compose an agent skill-router did not
generate — a second *agent source*. The trigger has now fired:
agent-roster's six SDLC stage agents (triage, requirements,
sprint-planning, test-authorship, code-generation, investigation) are a
natural workflow, and they are generated by agent-roster, not
skill-router.

Shipping more harnesses did not fire the trigger (ADR-009's amendment:
the harness axis is skill-router's existing business). A second agent
source does.

## Decision

The workflow module moves to a new repository, **skill-workflows**:

- The manifest format and validator (`workflows.json`,
  `loadWorkflows`), the three runners (pi `run-workflow` skill, Claude
  Code `run-workflow` skill, Vibe `workflow-orchestrator` mode), and the
  lockstep duty (ADR-010) all migrate.
- skill-workflows adds an **agent registry** (`agents.json`): the
  agent-agnostic interface ADR-009 anticipated. An entry is a name plus
  per-harness presence (pi agent path, Claude agent path, Vibe TOML
  path, each optional). Steps reference agents by registry name;
  runners dispatch by name on each harness and use registry paths for
  install-time existence checks and docs.
- The workflow spec stays minimal — `(agent, task, output)` per step —
  unchanged from ADR-009. agent-roster's richer stage discipline (typed
  knowledge artifacts, review gates) lives in task text in v1; the
  interface grows only when a second consumer demonstrates need
  (one consumer is a hypothetical seam).
- skill-router keeps its generated agents, `repos.json`, and everything
  else; it stops shipping workflow runners and its example workflows
  move to skill-workflows (or are dropped there in favor of better
  examples — the plan decides). ADR-009 gets a closing note: trigger
  fired, module extracted, seam held.

## Consequences

- Two installs where there was one: skill-router for agents, then
  skill-workflows for workflows. Both installers are idempotent and
  independent.
- skill-workflows owns the lockstep duty going forward; its ADR-001
  restates the three-runner contract.
- The runners' dispatch-by-name works unchanged on pi (subagent by
  name), Claude Code (Task by agent name), and Vibe (spawn
  `config_name`); the registry's paths are verification and docs, not a
  new dispatch mechanism.
- agent-roster gains a Vibe story only if its agents gain Vibe TOMLs —
  the registry marks per-harness presence optional, so a workflow whose
  step agent lacks a harness simply fails there with the runner's
  stop-and-report contract.
