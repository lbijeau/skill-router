A switchboard for agent skills

One clean-room agent per skill repo

skill-router pins 13 upstream skill repos and generates an isolated agent for each — for pi, Mistral Vibe and Claude Code — so every agent behaves like its own repo's author intended, independent of your catalog, and that repo's skill content never piles into your own session. A catalog-driven router picks the best skill across all of them and returns only the recommendation, so the catalog's bulk never enters your session either.

Install

  • git clone https://github.com/lbijeau/skill-router ~/repositories/skill-router
  • cd ~/repositories/skill-router
  • ./install.sh install clone, generate, wire
  • ./install.sh update pull, regenerate, deltas
  • ./install.sh status read-only health table

After install, run /reload in pi and Vibe. Claude Code needs one restart if ~/.claude/agents/ is new; pass --no-claude to skip all Claude Code changes.

Route

How a repo becomes an agent

Six stops, run end to end by ./install.sh install or update. Everything is derived from one manifest; nothing is configured twice.

  1. Stop 01

    Manifest

    repos.json holds one entry per repo: name, url, description, persona, plus optional skillSource / pathExclude curation — the single source of truth.

  2. Stop 02

    Clone

    Each repo is shallow-cloned into skills/<name>/ — gitignored, never committed. update pulls --ff-only; a failed pull leaves the clone as-is.

  3. Stop 03

    Discover

    Every clone is walked for directories containing SKILL.md; frontmatter is parsed and the curation rules applied. Skills are deduped by name.

  4. Stop 04

    Generate

    One agent per repo, restricted to that repo's skills: pi markdown, Vibe TOML, Claude Code markdown. A repo with zero skills gets no agent — its entry is kept for later.

  5. Stop 05

    Wire

    Idempotent settings edits, always with a .bak backup: pi agentScanDirs, Vibe agent_paths plus read allowlist, Claude Code agents dir and two Read permissions.

  6. Stop 06

    Catalog + router

    catalog/skill-catalog.md is rebuilt every run. The route-skill router reads it, opens the winning SKILL.md, and returns only the recommendation — the catalog's bulk never enters your session.

Terminals

Three targets, three kinds of clean room

Each target receives its own generated artifacts; skills are read as files inside the spawned agent, never loaded into your own session. How complete that isolation is differs per tool.

pi

agents/<name>.md

The agent loads exactly its repo's skills — never your catalog — and is tool-restricted to read-only by default.

Generated with inheritSkills: false, an explicit skills: list and skillPath: ../skills/<name>. Unless the manifest marks the repo "tools": "full", it also gets tools: read, grep, find, ls — no shell exec, no file write. Wiring adds subagents.agentScanDirs to your settings, so every agent is spawnable from any project.

Mistral Vibe

agents-vibe/<name>.toml

The subagent cannot load the parent's skill catalog, and is tool-restricted to read-only by default.

Each TOML sets agent_type = "subagent" and disabled_tools = ["skill"] — that is the clean room. Unless the manifest marks the repo "tools": "full", it also gets enabled_tools = ["read_file", "grep"] — no shell exec, no file write. Its skill table uses ~-anchored paths, and depth-pattern read allowlist entries auto-approve clone reads from any project.

Claude Code

agents-claude/<name>.md

Only Read, Grep and Glob — and no CLAUDE.md.

No Skill tool, no MCP, no Bash; skills are read as plain files from this checkout. Verified by a live probe; re-check after Claude Code upgrades, since it can change with versions. The installer only writes files it owns, marked with a generated-by marker.
